# Contributing

Cylindarr takes issues and suggestions. It does not take pull requests or code.

Pull requests are closed without review, however good the code in them is. If you want Cylindarr to work differently for you, the [AGPL](LICENSE) lets you fork it and change what you like. If you want it to work differently for everyone, open an issue and make the case.

## What helps

- **Bug reports.** What you expected, what happened, and the version (at the foot of every page). For a failed video, paste the reason shown beside it on the front page and the lines around it in the journal. The reason usually tells the whole story, because Cylindarr records why a download failed, not just that it did. Take out your host names, addresses, cookies, and API key first.
- **Setups it hasn't met.** AMD and NVIDIA encoders, Emby, arm64 machines, NAS shares with strange file name rules. Say what you run and what broke.
- **YouTube changed something.** When a video fails for a reason Cylindarr doesn't recognise, the yt-dlp output shown with it is exactly what's needed, along with the yt-dlp version from the access line at the top of the front page.
- **Suggestions.** Features, accommodations for your setup, clearer wording on a page. Describe what you're trying to do rather than the button you want; there may be a better way to get there.

## What doesn't

- Pull requests, patches in issues, and links to a fork with the change made. Describe the change instead.
- Requests to download purchased, rented, or DRM-protected content. Cylindarr doesn't, and won't.
